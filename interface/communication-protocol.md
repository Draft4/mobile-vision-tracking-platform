# RK3588 到 STM32 视觉测量通信协议

- 状态：初始约定（v0.1）
- 适用范围：视觉 RK3588 到云台 STM32
- 最后更新：2026-08-21

## 1. 目的与当前范围

本协议用于将 RK3588 产生的视觉测量单向发送给 STM32。当前版本只传输：

- 当前视觉任务是靶标检测还是无人机检测；
- 当前是否产生了有效目标测量；
- 目标相对当前相机光轴的偏航和仰角误差；
- 相机帧号、跟踪编号、置信度和测量年龄。

v0.1 不定义 STM32 到 RK3588 的任何消息，不传输云台角度、电机状态、限位、故障、
控制参数或应答信息，也不通过 UART 选择或切换视觉任务。

RK3588 在启动视觉程序时通过本地配置或启动参数选择 `TARGET` 或 `DRONE`，运行过程中
暂不切换。消息中的 `mode` 只用于告知 STM32 当前测量来自哪一种视觉任务。

角度方向、坐标系及结果语义以
[坐标系与方向约定](coordinate-system.md)为准。本文件是双方实现 UART 编解码时的
共同依据；若与早期聊天或临时测试代码不一致，以本文件为准。

## 2. 模块职责

### 2.1 RK3588

- 启动唯一的视觉运行进程并独占相机；
- 根据本地配置或启动参数运行靶标检测或无人机检测与跟踪；
- 把两种任务转换为相同语义的视觉测量消息；
- 持续发送当前任务、检测状态和角度误差；
- 不负责电机 PID、机械限位或最终安全保护。

### 2.2 STM32

- 校验并解析视觉测量；
- 根据模式、状态、有效标志、年龄和本地超时判断测量是否可用；
- 负责 PID、电机控制、方向映射、机械限位和通信失联保护；
- 目标丢失、测量过期或通信中断时停止使用视觉误差；
- 激光使能独立于视觉模式，任何视觉消息都不得自动开启激光。

## 3. 物理接口

### 3.1 UART 参数

| 参数 | 约定 |
| --- | --- |
| 波特率 | 115200 bit/s |
| 数据位 | 8 bit |
| 校验位 | None |
| 停止位 | 1 bit |
| 硬件流控 | None |
| 简写 | 115200 8N1 |

### 3.2 接线

v0.1 只要求单向传输：

```text
RK3588 UART_TX  -> STM32 UART_RX
RK3588 GND      -- STM32 GND
```

可以为后续双向通信预留下面这根线，但 v0.1 软件不使用：

```text
RK3588 UART_RX  <- STM32 UART_TX    # 预留
```

接线前必须根据实际 RK3588 载板和 STM32 硬件资料确认 UART IO 电压。只有双方均为
3.3 V TTL 时才可直接连接；若一侧为 1.8 V，必须增加合适的电平转换器。TTL UART
不得直接连接采用正负电压的 RS-232 接口，也不要用 UART 排针的电源脚给另一块主板
供电。

最终设备中的串口线应尽量短，远离电机相线、PWM 和大电流电源线，并使用可靠的带锁
连接器。实际开发板的 UART 编号、排针、设备树配置和 Linux 设备节点待硬件型号确定后
补充到对应模块 README。

## 4. 通用编码规则

- 每个数据帧以 `0xA5 0x5A` 开始；
- 协议版本固定为 `0x01`；
- 多字节整数统一使用小端序；
- 有符号整数使用二进制补码；
- 帧长度字段表示包含帧头和 CRC 在内的完整帧长度；
- 接收方不得假设一次 UART 或 DMA 接收恰好对应一个完整数据帧；
- 未定义的标志位发送时必须置零，接收时暂时忽略；
- 数据帧使用 `CRC-16/CCITT-FALSE`，CRC 自身不参与计算。

CRC 参数如下：

| 参数 | 值 |
| --- | --- |
| Polynomial | `0x1021` |
| Init | `0xFFFF` |
| RefIn / RefOut | false / false |
| XorOut | `0x0000` |
| 存储顺序 | 低字节在前，高字节在后 |

双方实现必须通过标准校验向量：ASCII 字符串 `123456789` 的结果应为 `0x29B1`。

## 5. 枚举定义

### 5.1 视觉模式 `VisionMode`

| 数值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `IDLE` | 当前未运行检测任务 |
| 1 | `TARGET` | 靶标检测任务 |
| 2 | `DRONE` | 无人机检测与跟踪任务 |

### 5.2 跟踪状态 `TrackingState`

| 数值 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `SEARCHING` | 当前图像未发现可用目标 |
| 1 | `TRACKING` | 当前图像产生了有效测量 |
| 2 | `TEMP_LOST` | 当前图像未产生新测量，但视觉会话尚未超时 |
| 3 | `FAULT` | 检测器、相机或视觉运行过程发生故障 |

## 6. 消息类型

v0.1 只定义一种消息：

| 数值 | 名称 | 方向 | 长度 |
| ---: | --- | --- | ---: |
| `0x20` | `VISION_MEASUREMENT` | RK3588 -> STM32 | 32 字节 |

Python 参考编解码实现位于
[`vision/src/gimbal_protocol.py`](../vision/src/gimbal_protocol.py)。该模块不访问 UART
硬件，可在开发电脑和 RK3588 上使用相同测试向量验证编码结果。

## 7. 视觉测量消息

### 7.1 `VISION_MEASUREMENT`（RK3588 -> STM32）

| 偏移 | 长度 | 类型 | 字段 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 2 | bytes | `sof` | 固定 `A5 5A` |
| 2 | 1 | uint8 | `version` | 固定 `1` |
| 3 | 1 | uint8 | `message_type` | 固定 `0x20` |
| 4 | 1 | uint8 | `frame_length` | 固定 `32` |
| 5 | 1 | uint8 | `flags` | bit0 为 `angles_valid`，其余置零 |
| 6 | 2 | uint16 | `packet_sequence` | 每发送一包递增，自然回绕 |
| 8 | 4 | uint32 | `frame_id` | 产生本次结果的相机帧号 |
| 12 | 4 | uint32 | `track_id` | 当前视觉跟踪会话编号，无编号时为 `0` |
| 16 | 4 | int32 | `yaw_error_urad` | 左正右负，单位为微弧度 |
| 20 | 4 | int32 | `elevation_error_urad` | 上正下负，单位为微弧度 |
| 24 | 2 | uint16 | `measurement_age_ms` | 采图到发送的年龄，最大值饱和为 `65535` |
| 26 | 2 | uint16 | `confidence_permille` | 置信度 `0～1000` |
| 28 | 1 | uint8 | `tracking_state` | `TrackingState` |
| 29 | 1 | uint8 | `mode` | 产生结果的 `VisionMode` |
| 30 | 2 | uint16 | `crc16` | 对字节 0～29 计算 |

角度编码方式：

```text
yaw_error_urad       = round(yaw_error_rad * 1_000_000)
elevation_error_urad = round(elevation_error_rad * 1_000_000)
```

STM32 转换回弧度：

```text
yaw_error_rad       = yaw_error_urad / 1_000_000
elevation_error_rad = elevation_error_urad / 1_000_000
```

角度是目标相对当前相机光轴的原始角误差，不是云台绝对目标角度，也不是电机速度、
电流或 PWM 命令。第一版不包含相机到云台安装外参补偿、预测、PID、限幅或死区。

只有同时满足以下条件时，角度字段才有效：

```text
flags.angles_valid == 1
tracking_state == TRACKING
mode == TARGET 或 DRONE
```

在 `IDLE`、`SEARCHING`、`TEMP_LOST` 或 `FAULT` 状态下，RK3588 必须把
`angles_valid` 置零，角度和置信度字段发送 `0` 作为占位。STM32 必须根据状态和标志位
忽略这些占位值，不能把它们解释成“误差为零”或继续使用上一帧角度。

`measurement_age_ms` 由 RK3588 使用本机单调时钟计算。因为 v0.1 没有 STM32 到
RK3588 的时间同步消息，STM32 不得把 RK3588 的原始时间戳与自身时钟直接比较。

## 8. RK3588 启动和发送行为

v0.1 的视觉任务由 RK3588 本地指定。例如后续统一入口可以采用下列形式之一：

```text
python -m vision.src.vision_runtime --mode target
python -m vision.src.vision_runtime --mode drone
```

也可以从本地配置文件读取启动模式。具体命令在统一视觉入口实现后补充到
`vision/README.md`，但无论采用哪种方式，同一时刻只能有一个进程打开相机。

启动顺序如下：

```text
1. RK3588 启动统一视觉进程。
2. 根据本地配置或启动参数确定 TARGET 或 DRONE。
3. 打开相机并初始化对应检测器。
4. 打开 UART。
5. 每得到一个新的检测结果就发送一帧 VISION_MEASUREMENT。
6. 未检测到目标时仍发送 SEARCHING 或 TEMP_LOST，明确使角度失效。
7. 相机或检测器发生故障时发送 FAULT；无法继续发送时由 STM32 本地超时保护。
```

运行过程中不接受来自 STM32 的模式指令。切换任务需要停止当前视觉进程，再使用新的
本地启动参数或配置重新启动；整车如何提供开机模式选择留待后续设计。

## 9. 接收、超时与安全行为

### 9.1 字节流解析

STM32 应使用字节流状态机或环形缓冲区：

1. 查找连续的 `A5 5A`；
2. 读取版本、消息类型和总长度；
3. 等待完整的 32 字节；
4. 校验长度、版本和 CRC；
5. 解析消息；
6. 校验失败时丢弃本帧并继续搜索下一个帧头。

禁止把 UART 一次中断或 DMA 回调的数据长度当成协议帧边界。STM32 的 UART 中断或
DMA 回调只负责把字节放入缓冲区，PID 和电机控制不得放在接收回调中执行。

### 9.2 序号

`packet_sequence` 每发送一个测量帧递增，`65535` 后自然回到 `0`。STM32 可用它识别
重复包和统计丢包，但不能仅因自然回绕而判定通信故障。`frame_id` 用于确认测量来自哪一
幅相机图像，同一个 `frame_id` 不应被重复当作新的控制测量累加使用。

### 9.3 默认时限

以下数值是首次联调的安全起点，最终应根据两种检测任务的实测帧率和端到端延迟 P95
共同调整，并在协议修订时记录：

| 检查 | v0.1 默认值 | 超时行为 |
| --- | ---: | --- |
| 测量年龄上限 | 100 ms | 不使用该角度 |
| 未收到新有效测量 | 150 ms | 视觉控制输出减为零，不复用旧角度 |
| 未收到任何 CRC 正确的测量消息 | 500 ms | 判定视觉通信离线 |

STM32 的通信超时使用自身本地时钟，从最后一次收到对应有效消息的时刻计算。CRC 正确只
说明数据帧没有检测到传输损坏，并不能替代模式、状态、年龄、序号和本地超时检查。

### 9.4 STM32 接受角度的必要条件

STM32 只有同时满足以下条件时才可把角度交给云台控制器：

```text
消息版本、类型、长度和 CRC 正确
mode 是已支持的 TARGET 或 DRONE
tracking_state == TRACKING
angles_valid == 1
measurement_age_ms 未超过上限
packet_sequence / frame_id 表示新测量
云台未故障且未触发相关限位
本地通信未超时
```

任一条件失效时，应立即把视觉测量标记为无效，并由云台控制器按照安全策略减速或停转。
不得继续复用最近一次有效角度。

## 10. 第一版联调顺序

1. 使用 3.3 V USB-TTL 模块分别验证 RK3588 发送和 STM32 接收；
2. 双方使用标准校验向量验证 CRC 实现一致；
3. 不连接电机，固定发送 `+0.1 rad` 偏航和 `-0.05 rad` 仰角，确认 STM32 解码为
   `+100000 urad` 和 `-50000 urad`；
4. 分别启动 `TARGET` 和 `DRONE`，确认消息中的模式正确；
5. 验证 `SEARCHING`、`TEMP_LOST` 和 `FAULT` 不会被当作零误差；
6. 主动制造错误帧、半帧和粘包，确认解析器能够恢复；
7. 拔掉 UART，确认 STM32 在约定时间内使视觉控制失效；
8. 连接电机后限制速度，一次只验证一个轴的正负方向；
9. 整机闭环测试期间保持激光关闭，完成超时、限位和故障测试后再单独评审激光使能。
