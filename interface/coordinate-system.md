# 坐标系与方向约定

状态：初始约定（v0.1）  
适用范围：底盘、云台、视觉以及模块间通信  
最后更新：2026-08-13

## 1. 为什么需要统一约定

本项目的相机安装在两轴云台上，用于识别、定位和跟踪移动目标。图像、相机、云台和底盘天然使用不同的坐标表达。如果各模块各自理解“左、右、上、下”和角度正负，单模块可能工作正常，整机联调时却会出现反向跟踪、轴交换或角度符号错误。

本项目采用机器人领域常见的 ROS REP-103 约定作为基础：

- 所有三维笛卡尔坐标系使用**右手系**；
- 车体坐标系使用 `x` 向前、`y` 向左、`z` 向上；
- 相机另设光学坐标系，使用 `x` 向右、`y` 向下、`z` 向前；
- 长度使用米（m），时间使用秒（s），算法与通信中的角度默认使用弧度（rad）。

参考标准：

- [ROS REP-103：单位与坐标系约定](https://reps.openrobotics.org/rep-0103/)
- [ROS REP-105：移动机器人坐标系](https://reps.openrobotics.org/rep-0105/)

即使项目暂时不使用 ROS，也采用这套命名和方向，方便使用现有视觉、标定、仿真与机器人软件。

## 2. 总体原则

1. **坐标系方向不随电机接线改变。** 电机、编码器或舵机方向相反时，只修改该设备的方向配置。
2. **数据必须注明所属坐标系。** 不使用含义不明的 `x`、`y`、`angle`；优先使用 `target_x_camera`、`yaw_error` 等名称，或随消息传递 `frame_id`。
3. **角度必须注明含义和单位。** 公共接口默认弧度；界面显示和人工调试可以使用度，但变量名或消息中应写明 `_deg`。
4. **像素误差和空间角度不是同一个量。** `pixel_error_u` 不能直接当作云台角度发送。
5. **先转换到统一逻辑方向，再进入控制器。** 禁止在不同代码位置零散添加负号修正方向。

## 3. 坐标系总览

初期推荐使用下面的坐标系关系：

```text
odom
└── base_link
    └── gimbal_yaw_link
        └── gimbal_pitch_link
            └── camera_link
                └── camera_optical
```

- `odom`：小车启动位置附近建立的局部固定坐标系；短时间连续，但轮式里程计可能逐渐漂移。
- `base_link`：固定在底盘上的车体坐标系。
- `gimbal_yaw_link`：随云台偏航轴旋转的坐标系，原点位于偏航转轴中心。
- `gimbal_pitch_link`：随云台俯仰轴旋转的坐标系，原点位于俯仰转轴中心。
- `camera_link`：相机的机器人常规坐标系。
- `camera_optical`：视觉算法使用的相机光学坐标系。

当前复现阶段不强制建立 `map`。以后增加全局定位时，再使用标准关系：

```text
map -> odom -> base_link
```

## 4. 底盘坐标系 `base_link`

### 4.1 原点

建议将原点设置在底盘几何中心附近、云台偏航轴在底盘基准平面上的投影点。若机械布局不适合，也可以选轮轴中点或其他容易测量的位置，但确定后必须在机械图和标定参数中记录实际偏移。

### 4.2 轴方向

```text
俯视图：

                 +x 前
                   ↑
                   │
        +y 左  ←  O

+z 上：垂直于底盘平面向上
```

因此：

| 运动或位置 | 数值符号 |
| --- | --- |
| 目标在车体前方 | `x > 0` |
| 目标在车体后方 | `x < 0` |
| 目标在车体左侧 | `y > 0` |
| 目标在车体右侧 | `y < 0` |
| 目标在车体上方 | `z > 0` |
| 目标在车体下方 | `z < 0` |

## 5. 相机坐标系

常规机器人坐标系和相机光学坐标系确实不同。不要把视觉库输出的三维坐标直接当成 `base_link` 坐标。

### 5.1 `camera_link`

`camera_link` 采用和车体相同的右手系方向：

- `+x`：镜头朝向，即相机前方；
- `+y`：相机左方；
- `+z`：相机上方。

### 5.2 `camera_optical`

视觉算法、相机标定结果和常见相机模型使用：

- `+Xc`：图像右方；
- `+Yc`：图像下方；
- `+Zc`：沿光轴向前，指向镜头看到的目标。

```text
从相机背后沿拍摄方向观察：

                 +Xc 右
          O ─────────────→
          │
          │
          ↓ +Yc 下

+Zc 前：从镜头向被拍摄目标延伸
```

相机正前方的有效目标通常满足 `Zc > 0`。

### 5.3 两个相机坐标系的零位转换

当镜头处于机械零位，且忽略相机安装偏差时：

```text
camera_link.x =  camera_optical.Zc
camera_link.y = -camera_optical.Xc
camera_link.z = -camera_optical.Yc
```

写成矩阵为：

```text
[x]   [ 0  0  1] [Xc]
[y] = [-1  0  0] [Yc]
[z]   [ 0 -1  0] [Zc]
```

实际相机通常存在安装位置和小角度偏差，最终应通过机械测量或外参标定得到完整旋转和平移，不应长期依赖“完全对正”的假设。

## 6. 图像像素坐标系

图像坐标原点位于左上角：

- `u` 或 `pixel_x`：向右增大；
- `v` 或 `pixel_y`：向下增大；
- 图像中心或相机主点记为 `(cx, cy)`。

```text
(0, 0) ─────────────→ +u / 右
  │
  │        (cx, cy)
  │           ×
  ↓
 +v / 下
```

定义原始像素误差：

```text
pixel_error_u = target_u - cx
pixel_error_v = target_v - cy
```

| 目标相对画面中心的位置 | `pixel_error_u` | `pixel_error_v` |
| --- | ---: | ---: |
| 右侧 | 正 | — |
| 左侧 | 负 | — |
| 下方 | — | 正 |
| 上方 | — | 负 |
| 中心 | 0 | 0 |

注意：`(cx, cy)` 优先使用相机标定得到的主点，而不是始终使用 `(width/2, height/2)`。

## 7. 云台角度与目标角误差

### 7.1 偏航角 `yaw`

偏航遵守绕 `+z` 轴的右手定则：

- 从上方俯视，逆时针为正；
- 云台向左转为正；
- 云台向右转为负；
- 零位为镜头指向底盘正前方。

```text
yaw > 0：向左
yaw < 0：向右
```

### 7.2 俯仰与仰角 `elevation`

严格右手系中，绕 `+y` 轴的正旋转会使镜头朝下。为了让控制和调试更直观，公共跟踪接口不直接使用含义容易混淆的 `pitch`，统一使用目标仰角 `elevation`：

- 镜头或目标向上为正；
- 镜头或目标向下为负；
- 水平向前为零。

如果数学库或机器人模型使用绕 `+y` 的右手俯仰角 `pitch_rh`，则：

```text
elevation = -pitch_rh
```

变量中不要只写 `pitch`。应明确写成 `elevation` 或 `pitch_rh`，避免把两套符号混用。

### 7.3 从像素计算角误差

在图像已经去畸变，并且已知相机内参 `fx`、`fy`、`cx`、`cy` 时，可用下式得到目标相对光轴的近似角误差：

```text
yaw_error       = atan2(cx - target_u, fx)   # 左为正、右为负
elevation_error = atan2(cy - target_v, fy)   # 上为正、下为负
```

对应关系为：

| 目标位置 | 像素误差 | 逻辑角误差 | 云台应运动 |
| --- | --- | --- | --- |
| 画面右侧 | `pixel_error_u > 0` | `yaw_error < 0` | 向右 |
| 画面左侧 | `pixel_error_u < 0` | `yaw_error > 0` | 向左 |
| 画面下方 | `pixel_error_v > 0` | `elevation_error < 0` | 向下 |
| 画面上方 | `pixel_error_v < 0` | `elevation_error > 0` | 向上 |

这两个角误差是目标相对**当前相机光轴**的误差，不是目标在 `base_link` 或 `odom` 中的绝对方向。要得到绝对方向，还必须结合当前云台角度和各坐标系外参。

## 8. 三维目标方向

若视觉模块得到目标在 `camera_optical` 中的三维坐标 `(Xc, Yc, Zc)`，则目标相对相机的左正方位角和上正仰角可以写为：

```text
target_yaw       = atan2(-Xc, Zc)
target_elevation = atan2(-Yc, sqrt(Xc^2 + Zc^2))
```

单目相机只凭一个普通目标框通常不能得到可靠的绝对深度。若需要以米为单位的位置，还需要已知目标尺寸、PnP、双目、深度相机或其他测距信息，并明确说明所采用的方法和误差范围。

## 9. 电机、编码器与舵机方向

不同电机安装、驱动器接线和编码器相序可能导致原始数值方向不同。硬件层统一使用下面的转换思路：

```text
logical_value = direction * (raw_value - zero_offset) * scale
```

- `direction` 只能取 `+1` 或 `-1`；
- `zero_offset` 为机械零位对应的原始值；
- `scale` 将计数或脉宽转换为标准单位；
- 转换后的逻辑值必须满足本文档的方向约定。

方向参数应集中放在云台或底盘配置中，例如：

```yaml
gimbal:
  yaw_direction: 1
  elevation_direction: -1
```

不要为了修正电机反转而修改视觉坐标系，也不要在 PID 输入、串口解析和电机输出等多个位置重复添加负号。

## 10. 推荐的接口命名

推荐使用以下名称：

| 名称 | 单位 | 正方向或含义 |
| --- | --- | --- |
| `target_u`, `target_v` | pixel | 右正、下正的目标像素位置 |
| `pixel_error_u` | pixel | 目标在画面右侧为正 |
| `pixel_error_v` | pixel | 目标在画面下方为正 |
| `yaw_error_rad` | rad | 目标在当前光轴左侧为正 |
| `elevation_error_rad` | rad | 目标在当前光轴上方为正 |
| `gimbal_yaw_rad` | rad | 云台向左为正 |
| `gimbal_elevation_rad` | rad | 云台向上为正 |
| `target_position_camera_optical` | m | `(Xc右, Yc下, Zc前)` |
| `target_position_base_link` | m | `(x前, y左, z上)` |

消息中不要同时发送没有单位后缀的 `yaw` 和用度表示的数值。若受 MCU 带宽或定点数限制，可以传输毫弧度（mrad）或缩放整数，但协议必须明确缩放比例。

## 11. 联调检查

首次接入或改动方向配置后，按以下顺序检查：

1. 将目标放在画面中心，确认两个像素误差接近零；
2. 将目标移到画面右侧，确认 `pixel_error_u > 0`、`yaw_error < 0`；
3. 将目标移到画面上方，确认 `pixel_error_v < 0`、`elevation_error > 0`；
4. 单独发送正 `yaw` 命令，确认云台向左运动；
5. 单独发送正 `elevation` 命令，确认云台向上运动；
6. 闭环前先限制速度和角度范围，确认目标偏向任意一侧时，云台都会缩小误差而不是扩大误差；
7. 记录实际相机安装偏移、云台零位和方向参数。

若第 4 或第 5 步方向错误，只修改对应硬件的 `direction` 参数；若第 2 或第 3 步错误，检查视觉坐标转换；不要同时修改两边来“凑巧抵消”。

以下内容需要机械安装和硬件选型确定后补充：

- `base_link` 原点的最终机械位置；
- 偏航轴、俯仰轴和相机光心之间的平移量；
- 云台机械零位和运动限位；

这些参数确定后，应更新本文档和对应模块 README，并通过第 11 节的联调步骤验证。
